Chapter 01

High-Level Architecture & Request Lifecycle

Earthquick is built on a monolithic Laravel 11 architecture utilizing server-rendered Blade templates coupled with targeted AJAX micro-endpoints (for cart drawer updates and instant search suggestions). This design prioritizes speed, SEO crawlability, and zero JavaScript build step friction.

1.1 How a Request Travels from Browser to Database

Every single HTTP request sent to Earthquick follows an unalterable, predictable sequence of layers before a response is returned to the user's browser:

1. Browser Sends HTTP GET/POST
→
2. .htaccess Enforces SSL & Rewrite
→
3. public/index.php Bootstraps Laravel Kernel
→
4. routes/web.php Matches URI Pattern
5. Middleware Auth, Admin, CSRF
→
6. Controller Executes Business Logic
→
7. Eloquent / MySQL Reads/Writes Database
→
8. Blade View Renders HTML to Client
বাংলা ব্যাখ্যা (Understanding Request Lifecycle)

ব্রাউজার থেকে যখন কোনো কাস্টমার /shop/women অথবা /cart/add ইউআরএলে রিকোয়েস্ট পাঠান:

১. ওয়েব সার্ভার (.htaccess): সরাসরি অন্য কোনো ফাইলে যেতে দেয় না; সমস্ত ট্রাফিক public/index.php-তে পাঠায়।
২. রাউটার (routes/web.php): চেক করে ইউআরএলটি কোন কন্ট্রোলারের সাথে ম্যাচ করে (যেমন: CategoryController@showCategory)।
৩. মিডলওয়্যার (Middleware): চেক করে ইউজার অথেন্টিকেটেড কি না (যদি অ্যাকাউন্ট বা অ্যাডমিন পেজ হয়)।
৪. কন্ট্রোলার ও ডাটাবেজ: কন্ট্রোলার Eloquent Model (যেমন Product::where(...)) ব্যবহার করে MySQL থেকে ডাটা আনে।
৫. ভিউ (Blade): ডাটাগুলো HTML ফরম্যাটে সাজিয়ে কাস্টমারের ব্রাউজারে ফেরত পাঠায়।

Chapter 02

Database Design & Eloquent Relationships

The Earthquick database engine is strictly normalized in MySQL (InnoDB engine) with foreign key constraints, cascading deletions where appropriate, and indexed fields for high-concurrency catalog queries.

2.1 Entity Relationship Diagram (ERD) Overview

[CATEGORIES] 1 ———< hasMany >——— N [SUBCATEGORIES]
    |                                                |
    +————————+                              |
    |                 |                              |
    v                 v                              v
[USERS] 1 ———< hasMany >——— N [ORDERS] 1 ———< hasMany >——— N [ORDER_ITEMS] >——— [PRODUCTS]

2.2 Database Schema Specifications

Table Name Primary Columns & Types Relationship to Other Tables
users id (PK), name, email (unique, null), phone (unique), password, is_admin (boolean), city, address Has many orders (one customer can place multiple orders).
categories id (PK), name, slug (unique), image, description, is_active, sort_order Has many subcategories, has many products.
subcategories id (PK), category_id (FK), name, slug, is_active, sort_order Belongs to category, has many products.
products id (PK), category_id (FK), subcategory_id (FK, null), sku, name, slug, price, old_price, fabric, image, in_stock, stock_quantity, is_featured, is_new_arrival Belongs to category & subcategory, has many order_items, has many images.
orders id (PK), order_number (unique, e.g. EQ-2026-X), user_id (FK, null for guests), customer_name, customer_phone, delivery_zone (inside_ctg / outside_ctg), subtotal, delivery_fee, total, status Belongs to user (nullable), has many order_items.
order_items id (PK), order_id (FK), product_id (FK), product_name, unit_price, quantity, total_price Belongs to order, belongs to product. Captures historical price at checkout time!

2.3 Eloquent Relationships in Code

In Laravel, Eloquent models express these relationships with clean, object-oriented syntax:

Model Relationship Methods app/Models/Product.php & Order.php 
// In app/Models/Product.php
public function category(): BelongsTo {
    return $this->belongsTo(Category::class);
}

public function subcategory(): BelongsTo {
    return $this->belongsTo(Subcategory::class);

// In app/Models/Order.php

Chapter 03

Authentication & Role-Based Access Control (RBAC)

Bangladesh e-commerce users frequently prefer logging in with their 11-digit mobile phone numbers rather than remembering passwords or email addresses. Earthquick implements a Dual-Identifier Authentication Engine that seamlessly accepts either an email or a valid Bangladeshi mobile number in a single input field.

3.1 The Dual-Identifier Login Engine

In app/Http/Controllers/AuthController.php, the login() method evaluates whether the entered string contains an @ symbol using PHP's native filter_var():

Dual-Identifier Resolution app/Http/Controllers/AuthController.php 
$identifier = trim($request->input('identifier'));

// Automatically determine if user entered an Email address or Mobile Phone
$fieldType = filter_var($identifier, FILTER_VALIDATE_EMAIL) ? 'email' : 'phone';

$credentials = [
    $fieldType => $identifier,
    'password' => $request->password,
];

if (Auth::attempt($credentials, $request->boolean('remember'))) {
    $request->session()->regenerate();

    // Role-based automatic redirection
    if (Auth::user()->is_admin) {
        return redirect()->route('admin.dashboard');
    }
    return redirect()->intended(route('account.dashboard'));
}

3.2 Role Separation: Customer vs Administrator

Role authorization is enforced at the database level via the is_admin boolean column on the users table:

  • Customer (is_admin = false): Has access to customer dashboard (/account), order receipts, profile updates, and checkout. Accessing /admin/* results in 403 Forbidden.
  • Administrator (is_admin = true): Full access to admin orders, metrics, stock toggles, and product CRUD (/admin/*). The top navigation bar displays a prominent "Admin Panel" gold badge.
Admin Guard Middleware app/Http/Middleware/AdminMiddleware.php 
public function handle(Request $request, Closure $next): Response {
    if (!Auth::check()) {
        return redirect()->route('login')
            ->with('error', 'Please login with administrator credentials.');
    }

    if (!Auth::user()->is_admin) {
        abort(403, 'Unauthorized access. This area is reserved for administrators only.');
    }

    return $next($request);
}

নতুন কাউকে অ্যাডমিন সুবিধা দিতে চাইলে ২টি সহজ উপায় রয়েছে:

Chapter 04

Shopping Cart & AJAX Drawer Mechanism

Earthquick avoids the performance penalty and friction of forcing customers to register before adding garments to their bag. All shopping cart interactions are saved to the server session via CartController.php and synchronized instantaneously with the frontend slide-out drawer via AJAX.

4.1 Session Storage Structure & Variant Keys

Products are indexed in session('cart') using a compound variant key composed of the Product ID and the variant size: {product_id}_{slug_size} (e.g., 14_standard or 14_l). This ensures adding the same product in a different size does not overwrite the existing item:

Variant Key Calculation & Session Update app/Http/Controllers/CartController.php 
$product = Product::findOrFail($request->product_id);
$size = $request->input('size', 'Standard');
$cartKey = $product->id . '_' . Str::slug($size);

$cart = session()->get('cart', []);

if (isset($cart[$cartKey])) {
    $cart[$cartKey]['quantity'] += $quantity;
} else {
    $cart[$cartKey] = [
        'key'        => $cartKey,
        'id'         => $product->id,
        'name'       => $product->name,
        'price'      => (float) $product->price,
        'image'      => $product->image,
        'size'       => $size,
        'quantity'   => $quantity,
    ];
}

session()->put('cart', $cart);

4.2 AJAX Endpoints & Response Schema

The client JavaScript (in public/js/script.js) calls three primary AJAX endpoints using the browser's fetch() API with the CSRF token in the request header:

  • POST /cart/add — Adds item, returns updated item count and subtotal.
  • POST /cart/update — Increments or decrements quantity. Auto-removes item if quantity reaches 0.
  • POST /cart/remove — Deletes individual variant line item.

Chapter 05

Checkout Engine & Atomic Order Processing

The checkout architecture is designed with utmost financial integrity. It calculates localized Bangladeshi courier rates and guarantees that an order and all its items are saved together atomically using Database Transactions.

5.1 Local Delivery Rates (Chattogram vs. Rest of Bangladesh)

Earthquick's flagship atelier is located in Nasirabad, Chattogram. Delivery fees are applied deterministically based on customer region:

Inside Chattogram City (inside_ctg)
৳80 BDT • 2-3 Business Days
Outside Chattogram / All BD (outside_ctg)
৳150 BDT • 3-5 Business Days

5.2 Atomic Database Transactions Explained

In e-commerce, creating an order requires two distinct database inserts: creating the master record in orders, followed by inserting each individual product into order_items. If the server loses power or MySQL throws an error halfway through, an incomplete "orphan" order could be created.

To prevent this catastrophic data inconsistency, CheckoutController.php encapsulates the entire write operation inside DB::transaction():

Atomic Transaction Order Placement app/Http/Controllers/CheckoutController.php 
$order = DB::transaction(function () use ($request, $orderNumber, $subtotal, $deliveryFee, $total, $cart) {
    // 1. Insert Master Order record
    $newOrder = Order::create([
        'order_number'   => $orderNumber,
        'user_id'        => auth()->id(), // Automatically linked if customer logged in
        'customer_name'  => $request->customer_name,
        'customer_phone' => $request->customer_phone,
        'delivery_zone'  => $request->delivery_zone,
        'district'       => $request->district,
        'area'           => $request->area,
        'address'        => $request->address,
        'subtotal'       => $subtotal,
        'delivery_fee'   => $deliveryFee,
        'total'          => $total,
        'status'         => 'pending',
    ]);

    // 2. Persist individual line items with snapshot pricing
    foreach ($cart as $item) {
        OrderItem::create([
            'order_id'      => $newOrder->id,
            'product_id'    => $item['product_id'],
            'product_name'  => $item['name'],
            'unit_price'    => $item['price'],
            'quantity'      => $item['quantity'],
            'total_price'   => $item['price'] * $item['quantity'],
        ]);
    }

    return $newOrder;
});

// 3. Purge session bag and redirect to invoice confirmation
session()->forget('cart');
return redirect()->route('checkout.success', ['order_number' => $order->order_number]);
ডাটাবেজ ট্রানজ্যাকশন কেন প্রয়োজন? (Why DB::transaction is critical)

ধরুন একজন কাস্টমার ৩টি শাড়ি অর্ডার করেছেন। orders টেবিলে মূল অর্ডার তৈরি হলো, কিন্তু ইন্টারনেটে সমস্যা বা সার্ভার ক্র্যাশের কারণে order_items টেবিলে ২য় পণ্যটি সেভ হতে গিয়ে ব্যর্থ হলো।

DB::transaction ব্যবহার করার কারণে যদি কোনো একটি পণ্যেও ত্রুটি ঘটে, তবে আগের সমস্ত ইনসার্ট স্বয়ংক্রিয়ভাবে Rollback (বাতিল) হয়ে যাবে। ফলে কখনোই অসম্পূর্ণ বা ক্ষতিগ্রস্ত ডাটা ডাটাবেজে জমা হবে না।

6.2 Image Upload & Asset Management Pipeline

When an administrator uploads an image for a new product:

  1. Input Validation: Verifies file presence, size limits (under 5MB), and MIME types (jpeg, png, jpg, webp, svg).
  2. Directory Check: Checks if public/images/products/ exists; creates it recursively with 0755 permissions if absent.
  3. Unique Renaming: Combines epoch timestamp with the sanitized filename to prevent filename overwriting: time() . '_' . Str::slug($originalName) . '.' . $extension.
  4. Collision-Safe Slug Generation: If a product named "Crimson Jamdani" already exists, the slug generator appends an incrementing integer (e.g. crimson-jamdani-1, crimson-jamdani-2).
  5. Safe Image Purging: When a product is deleted, deleteProduct() checks if the image resides in images/products/ before calling @unlink(), ensuring default seeder brand assets (e.g., hero banners) are never deleted!

6.3 Dynamic Subcategory Filtering in Blade

To ensure administrators do not accidentally assign a "Nakshi Kantha" subcategory to the "Women" category, product-create.blade.php contains a lightweight vanilla JS listener:

Dynamic Category-Subcategory Linking resources/views/admin/product-create.blade.php 
function filterSubcategories() {
    const selectedCatId = categorySelect.value;
    const options = subcategorySelect.querySelectorAll('option');

    options.forEach(opt => {
        if (!opt.value) return; // Preserve 'None' option
        const optCatId = opt.getAttribute('data-category');
        if (!selectedCatId || optCatId === selectedCatId) {
            opt.style.display = 'block';
        } else {
            opt.style.display = 'none';
            if (opt.selected) subcategorySelect.value = '';
        }
    });
}

7.1 Open Graph, Twitter & Canonical Meta Tags

In resources/views/layouts/app.blade.php, standard meta slots are provided for child Blade views to override dynamically:

  • <link rel="canonical" href="@yield('canonical_url', url()->current())" /> — Prevents Google duplicate content penalties for paginated or filtered catalog queries.
